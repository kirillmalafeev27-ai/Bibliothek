# Как устроена генерация вопросов

Движок вопросов и ИИ-механика перенесены из «Костров до рассвета» (Lagerfeuer, ветка
`claude/intelligent-galileo-qhskqv`), а туда — из Morskoy. Задания сочиняет модель на сервере
игры, но не по запросу «сгенерируй 10 заданий по теме X»: промпт собирается из модулей с
инструкциями для ИИ, а ответ модели проверяет код. В игру попадают только задания, прошедшие
проверку.

```
игрок выбирает темы ──► AiQuestionProvider ──POST /api/generate-questions──► сервер
                         (очереди по темам)                                    │
        панель вопроса ◄── вопрос серии ◄── задания {format,text,display,…} ◄──┤
                                                                               ▼
                       промпт = уровень + правила темы + форматы + правила качества
                       модель (AI Tunnel) → текст с ключом ответов → разбор → проверка
```

## Инструкции для ИИ — `server/generation/`

Модули скопированы из «Костров» без изменений текста: правила, каталог форматов, уровни, сборка
промпта, проверка и разбор совпадают байт в байт (в коде поправлены только аннотации типов под
строгий `tsconfig` этой игры). Тест сверяет, что у каждой темы клиента есть правила. Тем 48:
«Kasus unterscheiden» (различение падежей, см. ниже) пришла из «Костров», в Morskoy её нет.

| Модуль                  | В Morskoy                    | За что отвечает                                                                        |
| ----------------------- | ---------------------------- | -------------------------------------------------------------------------------------- |
| `grammarRules.ts`       | `lib/grammar-rules.js`       | 48 грамматических тем: правило, дизайн задания, форматы, дистракторы, запреты          |
| `exerciseFormats.ts`    | `lib/exercise-formats.js`    | каталог из 9 форматов заданий с разобранными примерами                                 |
| `qualityRules.ts`       | `lib/quality-rules.js`       | общие правила: субстанция вариантов, качество дистракторов, список брака, самопроверка |
| `exercisePrompt.ts`     | `lib/exercise-prompt.js`     | уровни A1–C1 и сборка итогового промпта                                                |
| `exerciseValidation.ts` | `lib/exercise-validation.js` | проверка ответа модели: что промпт не гарантирует — проверяет код                      |
| `textFormat.ts`         | `quiz-generation.js`         | разбор текстового ответа: блок `AUFGABEN` и отдельный ключ `LÖSUNGEN`                  |
| `audioTasks.ts`         | `quiz-generation.js`         | задания на аудирование: промпт, разбор, запасные дистракторы                           |

Рядом — клиент модели (`server/ai.ts`: AI Tunnel или любой OpenAI-совместимый эндпоинт, модели
перебираются по порядку), озвучка (`server/tts.ts`: ElevenLabs с кэшем) и API (`server/api.ts`).
Один и тот же обработчик API работает и в `npm run dev` (плагин Vite), и в боевом сервере
(`server/index.ts`), так что поведение не расходится.

## Главная проблема, которую решает система

Типовой плохой вопрос:

```
Er versucht, den Bahnhof ___ finden.
A) zu     B) –     C) zum     D) um zu
```

Это не упражнение. Кто знает конструкцию, узнаёт ответ мгновенно; кто не знает — гадает из
четырёх. Проверяется не владение `Infinitiv mit zu`, а узнавание частицы.

Правильная версия той же темы:

```
Sein Zug fährt um sechs. (vorhaben – früh aufstehen)
A) Er hat vor, morgen früh aufzustehen.      ← верно
B) Er hat vor, morgen früh zu aufstehen.
C) Er hat vor, morgen früh aufstehen zu.
D) Er hat vor, morgen früh aufstehen.
```

Варианты — целые предложения из одного и того же материала, различаются только положением `zu`.
Угадать по длине или по «единственному осмысленному варианту» нельзя.

## Правило субстанции

Формулируется в `qualityRules.ts`: **вариант ответа должен содержать всю целевую структуру,
а не один элемент из неё.**

| Тема                                      | Что должно быть в варианте                        | Что запрещено           |
| ----------------------------------------- | ------------------------------------------------- | ----------------------- |
| Infinitiv mit zu                          | вся инфинитивная группа или предложение целиком   | `zu / – / zum / um zu`  |
| Падежи, артикли, склонение прилагательных | вся именная группа: `ihrer neuen Kollegin`        | `dem / den / der / des` |
| Perfekt, Passiv, Futur, модальные         | весь глагольный комплекс, лучше двойным пропуском | одно причастие          |
| Порядок слов, придаточные, рамка          | всегда целые предложения                          | обрывки                 |

Единственное исключение — когда целевое явление действительно одно слово: выбор союза
(`als / wenn / wann`), значение модального глагола, предлог при фиксированном управлении. Тогда
решение должен нести контекст (мини-диалог или однозначные слова-сигналы), а предложение — быть
не короче восьми слов.

## Форматы заданий — «формат квиза»

Задание в формате генератора — это инструкция по-русски (`text`), немецкий материал (`display`)
и ровно четыре варианта (`options`, `correct`). Для каждой темы в `grammarRules.ts` перечислено,
какие форматы подходят; в промпт попадают только они, вместе с разобранными примерами.

| id                | Формат                                              | Что даёт                                     |
| ----------------- | --------------------------------------------------- | -------------------------------------------- |
| `satzvarianten`   | выбор из четырёх целых предложений                  | снимает угадывание по длине                  |
| `umformung`       | преобразование (актив → пассив, презенс → претерит) | проверяет продуктивное владение              |
| `verbindung`      | соединить два предложения в одно                    | падеж и порядок слов сразу                   |
| `fehlerkorrektur` | найти и исправить одну ошибку                       | вариант «не исправлено» — сильный дистрактор |
| `dialog`          | мини-диалог, решает контекст                        | честный способ проверять значение            |
| `mehrfachluecke`  | два пропуска, матрица 2 × 2                         | половинное знание видно в статистике         |
| `wortstellung`    | собрать предложение из частей                       | целые предложения в вариантах                |
| `bedeutung`       | минимальная пара, все варианты грамматичны          | проверяет понимание, а не форму              |
| `luecke`          | классический пропуск, но со всей структурой         | базовый формат для падежей и форм            |

В блоке из 10 заданий нужно минимум 4 разных формата, не больше 4 заданий одного формата и
минимум 2 задания из сложных форматов (`umformung`, `verbindung`, `fehlerkorrektur`, `bedeutung`).

### Как задание выглядит в игре

Панель вопроса — столбец рукописи (`src/shared/QuestionPanel.ts`). У задания генератора
инструкция стоит мелким курсивом, как глосса писца, под ней — немецкий материал основным письмом
(реплики диалога — каждая с новой строки, тире висит слева), ниже — четыре таблички.
Варианты-предложения стоят столбиком во всю ширину с текстом по левому краю, короткие варианты —
сеткой 2 × 2 (порог — `isLongOptions`: четыре слова или три слова длиннее 24 знаков; у вопросов
банка вариантов длиннее двух слов нет, и их раскладка не меняется). Инициал-буквица у задания
генератора не рисуется: место нужнее тексту.

Шрифт подбирается сразу для всего задания (`fitSheet`): варианты 20 → 12 px, материал на 2 px
крупнее, инструкция 15 → 11 px; с 14 px раскладка уплотняется (меньше полей и межстрочных
интервалов), и только потом шрифт мельчает дальше. Если не встаёт и на минимуме, лист
прокручивается, а нижний край тает — видно, что ниже есть ещё варианты.

В раунде с заданиями генератора панель вопроса больше (`genLayoutSpec` в
`src/shared/layout.ts`): клетка библиотеки уступает с желаемых 40 px до минимальных 36 px, и
освободившееся место отходит заданию.

| Экран    | Панель с банком | Панель с генератором | Клетка  |
| -------- | --------------- | -------------------- | ------- |
| 390×844  | 366×300         | 366×344              | 40 → 36 |
| 412×915  | 388×371         | 388×415              | 40 → 36 |
| 768×1024 | 744×420         | 744×512              | 45 → 37 |
| 844×390  | 300×366         | 332×366              | 39 → 36 |
| 1280×800 | 435×776         | 538×776              | 72 → 63 |
| 375×667  | 365×190         | 365×220              | 39 → 36 |
| 360×640  | 350×190         | 350×193              | 36      |

По замерам `npm run test:quiz` на примерах каталога: на 390×844, 844×390, 1280×800 и больше все
девять форматов встают без прокрутки (на 390×844 предложения — в плотной раскладке, 14 px). На
невысоких телефонах (375×667, 360×640) панель упирается в правило «клетка не меньше 36 px», и
задания с четырьмя предложениями (`satzvarianten`, `umformung`, `verbindung`,
`fehlerkorrektur`, `wortstellung`) и аудирование прокручиваются; короткие форматы встают.

## Что проверяет код, а не промпт

`exerciseValidation.ts` отбраковывает то, что модель всё равно иногда присылает:

- не ровно 4 варианта, пустые или повторяющиеся варианты;
- пропуск `___` внутри варианта ответа;
- оборванное предложение (заканчивается на `...`);
- задание на пропуск (`luecke`, `mehrfachluecke`, `dialog`) без пропуска в материале — например,
  если до экрана дошла бы только первая реплика диалога, а варианты подставляются во вторую;
- расхождение номера правильного ответа и его текста — модель обязана продублировать ответ
  дословно, и это сверяется;
- **нарушение правила субстанции**: если все четыре варианта короче минимума для темы, задание
  отклоняется;
- варианты, отличающиеся по длине более чем в 5 раз;
- дубли внутри блока и повтор уже выданных заданий;
- перекос по форматам: лишние задания одного формата уходят в конец очереди.

Материал задания разбор берёт целиком — строку `Aufgabe:` и все строки за ней до вариантов:
реплики диалога модель часто пишет каждую с новой строки. Строки решения (`Lösung:`, `Antwort: C`,
`Erklärung:`) в материал не попадают.

Причины отбраковки пишутся в лог сервера (по-немецки, как в Morskoy) — по ним видно, на чём
спотыкается модель:

```
[Infinitiv mit zu B1] 8/12 Aufgaben übernommen; aussortiert: Füllwort-Optionen: Thema verlangt mindestens 3 Wörter je Option; doppelte Optionen
```

Сервер просит на 4 задания больше, чем нужно, — с запасом на брак; лишние задания ждут в пуле по
ключу «уровень × тема × лексика × Wortstellung» и уходят следующему запросу без обращения к модели.

## Уровни

`exercisePrompt.ts` разворачивает «уровень A2» в конкретные ограничения: длина предложения,
разрешённые и запрещённые структуры, пласт лексики, замечание о подходящих форматах. Без этого
«A2» для модели — пустой ярлык.

## Лексические темы

Лексическая тема задаёт мир заданий: «WORTSCHATZTHEMA: … Alle Aufgaben spielen in diesem
Themenfeld — Personen, Orte und Gegenstände stammen daraus. Das Grammatikthema bleibt trotzdem
der Prüfgegenstand.» Правила грамматики от неё не зависят, поэтому новая тема — это только строка
в `src/shared/questions/topics.ts`: сервер принимает любую лексическую тему короче 80 знаков, а
клиент предлагает только список (`sanitizeQuizConfig` отбрасывает неизвестные).

- **Повседневные (19, как в Morskoy и «Кострах»):** Begrüßung, Familie, Kindheit, Schule,
  Essen und Trinken, Tagesablauf, Wetter, Stadt, Hobbys und Freizeit, Reisen und Urlaub,
  Einkaufen, Natur und Umwelt, Wohnen, Kleidung, Körper und Gesundheit, Berufe, Verkehrsmittel,
  Feste und Feiertage, Medien und Technik.
- **Дополнительные (25):** сначала темы мира этой игры — Bibliothek und Bücher, Lesen und
  Literatur, Märchen und Sagen, Mittelalter und Burgen, Schatzsuche und Abenteuer, Nacht und
  Träume; затем шире повседневности, для уровней повыше — Tiere, Sport, Musik, Kunst und Museum,
  Film und Fernsehen, Restaurant und Café, Arzt und Krankenhaus, Haushalt, Gefühle und Charakter,
  Freundschaft und Liebe, Arbeit und Büro, Studium und Universität, Sprachen lernen, Geld und Bank,
  Post und Briefe, Länder und Kulturen, Geschichte, Wissenschaft und Forschung, Politik und
  Gesellschaft.

В выборе тем это одна группа-радио из трёх частей: «Любая» (тема на усмотрение генератора, но
разная внутри блока), повседневные и дополнительные.

## Клиент: темы, очереди, запасной путь

- **Выбор тем** (`Screens.quiz` в `src/ui/screens/Screens.ts`, кнопка «Вопросы» в меню) — шаги
  меню Morskoy в одной карточке: уровень A1–C1, лексическая тема, до пяти тем (свои наборы слов и
  грамматика), слот Wortstellung (порядок слов на материале первой грамматической темы) и
  аудирование. Кнопки «Готово», «Встроенный набор» и «Отмена» всегда внизу карточки. Выбор
  хранится в `localStorage` (`library:quiz`), под кнопками меню — строка с темами. При первом
  «Играть», если на сервере есть ключ генерации, выбор тем открывается сам (ответа сервера
  «Играть» ждёт не дольше 2,5 с).
- **`AiQuestionProvider`** (`src/shared/questions/`) — движок `QuestionManager` из Morskoy под
  интерфейс `QuestionProvider` серии: блок по 10 заданий на тему, темы чередуются, следующий блок
  запрашивается заранее (когда в очереди остаётся 5), показанные и ждущие в очереди задания
  уходят в `exclude`, варианты перемешиваются при каждом показе, неверно решённое задание
  возвращается через 4–6 вопросов того же раунда (12.3). Числа — в `balance.ai`.
- **Ожидание.** Раунд не начинается без вопроса (12.4): если к концу интро первое задание ещё не
  готово, мир стоит, а в интро и в панели — «Готовлю вопросы…» (до 45 с, потом — встроенный
  банк). Пауза во время ожидания работает как обычно; если задания пришли на паузе, раунд
  начнётся, когда игрок вернётся. Посреди раунда следующий вопрос всегда загружен заранее, но
  если очередь всё же опустела, панель ждёт до 1,5 с, и **всё это время мир тоже стоит** —
  ожидание генерации не должно стоить игроку времени (в «Кострах» ночь в это время шла).
- **Запасной путь.** Если генерации нет (сервер недоступен, игра раздаётся как статика) или
  модель не ответила — вопросы берутся из встроенного банка `bank.de.json`, игра не встаёт. Если
  на сервере просто нет ключа (`503`), замолкают только темы генератора: свой набор слов сервер
  отдаёт и без ключа. Адрес `?q=bank` — только встроенный банк, без выбора тем.
- **Аудирование.** Немецкой фразы на экране нет: она звучит сама, когда вопрос становится
  активным (если звук включён и таблички не заперты готовым действием), а кнопка «Слушать»
  повторяет её. Озвучка — `/api/tts` (ElevenLabs), без ключа — голос браузера. На паузе и в сцене
  поимки звук фразы останавливается.
- **Встраивание.** `mountLibrary` по-прежнему принимает любой `QuestionProvider`: если хозяин
  передаёт свой источник без выбора тем, кнопки «Вопросы» нет, и всё работает как раньше.

## Свои наборы слов — `server/vocab/`

Список слов учителя, а к нему задания, написанные вручную; модель здесь не участвует. В выборе тем
наборы стоят первыми («Свои наборы слов») и чередуются с грамматикой, как обычные темы. Уровень и
лексическая тема на них не влияют, ключ генерации им не нужен.

Первый набор — **Wortschatz für Sascha und Präpositionen** (`server/vocab/sascha.ts`): 20 слов с
предлогами (`stolz auf`, `froh über`, `zufrieden mit`, `die Einladung zu`, `die Warnung vor`…), на
каждое — четыре задания, по два на каждое умение:

| Вид            | Что на табличке                  | Варианты                                                                                        |
| -------------- | -------------------------------- | ----------------------------------------------------------------------------------------------- |
| `wortwahl`     | немецкий контекст, пропуск слова | четыре слова из списка, подходит по смыслу одно                                                 |
| `uebersetzung` | русская фраза                    | четыре немецких предложения: верное, с неверным предлогом, два с другими словами списка         |
| `praeposition` | пропуск предлога                 | четыре предлога                                                                                 |
| `kasus`        | пропуск «предлог + слово»        | матрица 2 × 2: верный и неверный предлог × верный и неверный падеж (`auf meine` / `auf meiner`) |

`tests/vocab.test.ts` проверяет каждое задание: варианты — только слова из списка, у верного
ответа — своё слово со своим предлогом, у перевода ровно один вариант с неверным предлогом, у
задания на падеж — матрица. Новый набор: файл по образцу `sascha.ts`, его название — в
`VOCAB_SETS` (сервер) и `VOCAB_TOPICS` (`src/shared/questions/topics.ts`), затем `npm test`.

## Темп и сложность

Задания генератора читаются в разы дольше слов банка, поэтому темп ученика для них считается
отдельно (`src/app/pacing.ts`): свой учёт на каждый уровень A1–C1 (`series:pace:gen:B1`…) и для
своих наборов слов (`series:pace:gen:vocab`). Пока ответов меньше пяти, берётся темп с ближайшего
уровня, где ученик уже отвечал, а если такого нет — значение по умолчанию: 11, 11, 12, 13 и 14 с
на A1–C1, 7 с для наборов слов. Пределы T_med — 4–30 с вместо 3–10 у банка.

Все правила игры заданы в единицах A, а A = T_med + 0,45 с. Поэтому раунд с заданиями генератора
в единицах A тот же, что с банком: библиотекарь ходит медленнее ровно настолько, насколько дольше
ученик читает задание. Уровни заново не подбирались. Учтены две разницы:

- **Разброс времени ответа.** Форматы разной длины, и время ответа на задания генератора
  разбросано сильнее (σ ≈ 0,65 против 0,5 у банка — оценка «Костров»). При той же медиане среднее
  время ответа выше, и без поправки раунд с генератором был труднее на 3–8 п. на уровнях 3–∞.
  Поэтому для единицы A медиана берётся с запасом ×1,12 (`balance.paceGenerated.allowance`),
  подобранным симуляцией так, чтобы тот же ученик выигрывал столько же, сколько с банком.
- **Показ ошибки** — 1,8 с вместо 1 с: верное предложение нужно успеть прочитать. В единицах A
  это даже меньше, чем у банка (0,13 A против 0,18 A).

Сверка — `npm run sim -- --compare-gen`: тот же ученик (p = 0,8), с банком — медиана 5 с и
σ = 0,5, с генератором — 12 с, σ = 0,65 и показ ошибки 1,8 с. Итоги — в `DECISIONS.md`,
«Сложность с заданиями генератора». Если задания генератора ученику труднее (верных меньше), раунд
труднее — так и должно быть: решает знание.

## API

| Метод  | Путь                            | Что делает                                                                                                                             |
| ------ | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/healthz`, `/health`           | `{"ok":true}` — проверка здоровья, не зависит от ключей                                                                                |
| `GET`  | `/api/quiz/status`              | настроены ли генерация и озвучка, список моделей                                                                                       |
| `POST` | `/api/generate-questions`       | `{level, grammarTopic, lexicalTopic?, isWortstellung?, count?, exclude?}` → `{questions: [{format, text, display, options, correct}]}` |
| `POST` | `/api/generate-audio-questions` | `{level, lexicalTopic?, count?, exclude?}` → `{questions: [{mode:'audio', text, display, audioText, options, correct}]}`               |
| `POST` | `/api/tts`                      | `{text}` → `audio/mpeg`                                                                                                                |

Тема должна быть из каталога (`resolveTopic`), иначе `400` — API не превращается в бесплатный
доступ к модели с произвольным текстом в промпте. Без ключа генерация отвечает `503`, и клиент
сразу переключается на встроенный банк. Свой набор слов (`grammarTopic` — его название) отдаётся
и без ключа; у заданий на перевод есть поле `displayLang: 'ru'` — материал по-русски. Ключи —
только в переменных окружения сервера (`AITUNNEL_API_KEY`, `ELEVENLABS_API_KEY`, см.
[`DEPLOY.md`](../DEPLOY.md)); в репозиторий они не попадают, `.env*` в `.gitignore`.

## Различение падежей

Темы Nominativ, Akkusativ, Dativ и Genitiv проверяют каждая свой падеж. «Kasus unterscheiden» (в
выборе тем стоит после Genitiv) проверяет само различение: по роли в предложении понять, какой
падеж нужен, и выбрать форму. Четыре варианта — одна и та же именная группа в четырёх падежах
(«ihr neuer Lehrer / ihren neuen Lehrer / ihrem neuen Lehrer / ihres neuen Lehrers»), и
предложение допускает ровно один; ступени по уровням и чередование «ядер» (подлежащее против
дополнения, Akkusativ против Dativ при глаголе, _wohin?_ против _wo?_, Genitiv как владелец) —
в `grammarRules.ts`.

Без ключа генерации тема молчит, как и остальные; для этого случая во встроенном банке есть
двенадцать коротких заданий на падежи (`kas-001` … `kas-012`) — в библиотечном антураже: «___
Bibliothekar hört jedes Geräusch», «Das Buch gehört ___ Bibliothek», «Ich lege das Buch auf ___
Pult» / «Das Buch liegt auf ___ Pult». `tests/bank.test.ts` проверяет, что верный вариант — форма
нужного падежа и рода, остальные — настоящие формы того же слова в других падежах и среди них есть
соседний падеж.

## Как добавить тему

1. Грамматическая: название — в `GRAMMAR_GROUPS` в `src/shared/questions/topics.ts`, запись — в
   `GRAMMAR_RULES` в `server/generation/grammarRules.ts` с полями `rule`, `design`, `formats`,
   `traps`, `avoid` (и ту же запись — в Morskoy и «Кострах», чтобы правила не разошлись). Если
   целевая структура больше одного слова — внести тему в `PHRASE_TOPICS` или `SENTENCE_TOPICS` в
   `server/generation/exerciseValidation.ts`.
2. Лексическая: строка в `BASE_LEXICAL_TOPICS` или `EXTRA_LEXICAL_TOPICS` в
   `src/shared/questions/topics.ts` — короткое немецкое название (тест проверяет длину и язык).
3. `npm test` — тесты проверяют, что у каждой темы клиента есть правила, все указанные форматы
   существуют, а лексическая тема доходит до промпта.

Если клиент присылает название в ASCII-транслитерации (`Praeteritum`, `Relativsaetze`), оно всё
равно найдётся: `resolveTopic` нормализует умлауты и знает список синонимов.
